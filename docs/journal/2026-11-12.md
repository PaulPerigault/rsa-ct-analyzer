# Journal of 2026-11-12

## Rewrite of the repository (D-001, D-002)

Starting point: three binaries chained through SQLite (cgo), an external C++ batch GCD, a module path on
a school forge, machine-specific paths in the YAML, one test that failed on Windows (a log file left open).
Read from the code before deciding: the cryptographic core was a small part of the total, and the
pipeline only moved certificates between processes.

Result: one binary, `scan`, `crawl` and `mock-log`, pure Go, batch GCD in `pkg/batchgcd`, checked against
the O(n²) definition. 52 top-level tests, `-race`, coverage between 87 and 98 % by package.

## Sample data

`dev/gen-testdata` derives every sample from a fixed seed (a deterministic PRNG, not `crypto/rand`) so two
runs give the same bytes; CI regenerates and compares. Go refuses to *validate* an RSA key whose primes
are adjacent (`|p - q| too small`), which is the very weakness `close-primes` tests; so only the CA has a
private key, the weak keys are public keys inside certificates signed by the CA.

## Real CT fixtures (D-008)

One `get-entries` of 32 entries from `argon2026h2` (plus `get-sth`), trimmed to four entries of
cloud-provider host names. The parser written against the RFC read them first time, including
precertificates whose certificate is in `extra_data`. The leaf parser now checks every length field and
bounds the encoded size; malformed cases are derived by mutating a real entry.
